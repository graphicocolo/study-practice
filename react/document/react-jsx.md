# 課題：JSX の書き方

**目標：** JSX の基本ルール（式の埋め込み・属性・条件分岐・リスト表示）を理解し、正しい JSX が書けるようになる

---

## 準備

`study-app/react-practice/src/components/` に新しいコンポーネントファイルを作成：

```
Study01Jsx.tsx
```

`App.tsx` から一時的に読み込んで、ブラウザで表示を確認しながら進める。

---

## 前提知識

| ルール | 内容 |
|---|---|
| ルート要素は1つ | 複数のタグを並べて return できない（`<>...</>` で包む） |
| タグは必ず閉じる | `<img>` や `<br>` も `<img />` のように自己終了させる |
| `{}` には式しか書けない | `if` / `switch` などの「文」は書けない |
| 属性は camelCase | `class` → `className`、`onclick` → `onClick` |

### ⑤ リストのレンダリング

```tsx
// 以下の配列を map でリスト表示する
// const fruits = ["apple", "banana", "orange"];

// <ul>
//   {fruits.map((fruit) => <li key={fruit}>{fruit}</li>)}
// </ul>

// key に index を使った場合と値そのものを使った場合で
// 何が違うか（配列の並び替え・削除が起きたときの挙動）を考える

// 何が違うかは、わからなかった（今回のデータでは影響はなかった）
// index を key にすると、並び替えや削除が起きたときに対応がずれる場合がある
```

【追記】index を key にして良いかの判断基準
- 問題ない場合：リストが固定（追加・削除・並び替えが起きない）、または完全に静的な表示のみ
- 避けるべき場合：途中への挿入・削除・並び替えが起きる、かつ各項目が
  state や uncontrolled input のような DOM 状態を持つ
→ 今回わからなかったのは、<li>{fruit}</li> が静的な表示だけで
  何も状態を持っていなかったため（index key でも value key でも見た目が同じになる）

【追記】違いを体感する実験のヒント
map の中に直接書いた <li> は自分の state を持てないので、
各行を別コンポーネント（例: FruitRow）に切り出し、中に <input> を置く
1. FruitRow を作り <input defaultValue={fruit} />（または useState）を持たせる
2. fruits.map((fruit, index) => <FruitRow key={...} fruit={fruit} />) とし、
   key を index版 / fruit版で切り替えられるようにする
3. 配列の先頭を削除するボタンを用意する（例: setFruits(fruits.slice(1))）
4. 各 input に文字を入力 → 先頭を削除 → input の中身がどうなるか観察する
   - key={index} の場合：削除後、各 input の「位置」に元の文字列が残り、中身がズレる
   - key={fruit} の場合：削除された項目の input ごと消え、残りは正しく内容を保持する

【追記】違いを体感する実験を行いました
確かに key={index} とすると、入力した値と削除した要素がずれ込む（他の果物の input に前の入力内容が残ってしまう）ことを確認できた。

## 確認ポイント

**JSX の `{}` に書けるものと書けないものの違いは？**

`{}` には「式（expression）」しか書けない。式は評価すると値になるもの（変数・演算・三項演算子・関数呼び出しなど）。`if` / `switch` / `for` は「文（statement）」で値を返さないため書けない。条件分岐したい場合は三項演算子か `&&` を使う。

**なぜ `class` ではなく `className` を使う？**

JSX は最終的に JavaScript のオブジェクトに変換される。`class` は JavaScript の予約語（クラス構文）と衝突するため、DOM の `className` プロパティに合わせて `className` を使う。

**リスト表示で `key` が必要な理由は？**

React は `key` を使って「どの要素が変わらず、どの要素が追加・削除・並び替えされたか」を判定する。`key` がないと差分検出の効率が落ち、意図しない再レンダリングやフォーム入力のズレなどのバグにつながる。index を key にすると、並び替えや削除が起きたときに対応がずれる場合がある。

**Fragment (`<>...</>`) は何のために使う？**

JSX は1つのルート要素を返す必要があるが、実際の DOM には余分な `<div>` を増やしたくないことがある。Fragment は DOM に何も残さず、複数の要素をまとめて1つの式として返すために使う。
